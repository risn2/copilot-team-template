# Lychee Redmine バーンダウン MVP 要求仕様

## 1. 背景
Lychee Redmine のスプリントで管理しているバックログポイントを使い、一般ユーザーが後からダッシュボードへ埋め込みやすい最小構成のユーザー別バーンダウン表示が必要である。

## 2. 目的
- Lychee Redmine のスプリント設定を表示期間の基準として扱う。
- 1ユーザー分のバーンダウンを最小構成で表示できる MVP を提供する。
- Redmine / Lychee Redmine 連携の前提、制約、未確定事項を文書化する。

## 3. スコープ
- In Scope:
  - スプリントを主軸にしたユーザー別バーンダウン表示の MVP 実装
  - 要求仕様、詳細設計、実装計画の追加
  - 埋め込みを想定した静的な UI とサンプルデータモデル
  - スプリント境界、ポイント定義、完了判定に関する前提の明記
- Out of Scope:
  - 実 Redmine / Lychee Redmine API・DB への本番接続
  - Redmine プラグイン化や認証連携
  - 管理者向け設定画面、複数プロジェクト横断集計、厳密な履歴再計算

## 4. ユースケース
- 一般ユーザーが 1 つのスプリントを選び、自分または指定ユーザーのバーンダウン推移を確認する。
- 将来のダッシュボード埋め込みに備えて、iframe で表示しやすい単一画面の UI を確認する。
- 実データ連携前に、スプリント主導のデータ契約と画面仕様を合意する。

## 5. 機能要件
- MVP はスプリント一覧から対象スプリントを選択でき、任意期間の自由入力は提供しない。
- MVP はユーザー一覧から 1 ユーザーを選択し、そのユーザーに紐づくバーンダウンのみを表示する。
- 画面は対象スプリント名、開始日、終了日、計画ポイント、完了ポイント、残ポイントを表示する。
- 画面はスプリント日次の残ポイント推移と理想線を表示する。
- データモデルはスプリント情報をトップレベルの主要オブジェクトとして扱い、バーンダウン系列は `sprintId` と `userId` に紐づける。
- MVP は Redmine 連携未実装でも動作できるよう、サンプル JSON データで表示できる。

## 6. 非機能要件
- 性能: ビルド工程や外部依存を増やさず、静的ファイルだけで表示できる。
- セキュリティ: 秘密情報、固定トークン、実運用用 URL を含めない。
- 可用性: データ読込失敗時はエラー状態を画面に表示する。
- 運用性: 実データ連携時に必要な前提と制約をドキュメントで参照できる。

## 7. 受け入れ基準
- `docs/requirements/`, `docs/design/`, `docs/implementation-plans/` に本機能向け文書が追加されている。
- 実装済み UI で、表示期間がスプリント開始日と終了日に従って表示され、任意日付範囲入力に依存していない。
- サンプルデータでユーザー別バーンダウン、サマリー、スプリント期間、理想線が表示される。
- ドキュメントに Redmine / Lychee Redmine 連携前提、スプリント境界の決定方法、制約が記載されている。
- 変更内容に秘密情報が含まれていない。

## 8. 未決事項
- Lychee Redmine のスプリント設定を取得する正式な API / DB 参照方法は別途確認が必要。
- 実運用でのバックログポイント保存先（カスタムフィールド名 / 専用テーブル）は環境依存である。
- 完了判定を Closed のみとするか、done ratio 100% も含めるかは導入先で確定が必要。
