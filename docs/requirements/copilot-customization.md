# Copilot カスタマイズ要求仕様

## 1. 背景
共通指示、カスタムエージェント、Agent Skills をチームで再利用する際、設定形式の陳腐化、不要な高コストモデルの固定、検証不足による品質低下を防ぐ必要がある。

## 2. 目的
- GitHub Copilot が認識できる形式で設定を提供する。
- 通常は Auto モデル選択を利用してプレミアム要求数を抑える。
- 高リスクな変更ではモデル選択に依存せず、検証とレビューで品質を担保する。

## 3. スコープ
- In Scope:
  - `.github/copilot-instructions.md`
  - `.github/agents/`
  - `.github/skills/`
  - 関連するテンプレートと利用手順
- Out of Scope:
  - 組織・Enterprise の Copilot ポリシー設定
  - 特定プロジェクト固有の実装規約

## 4. ユースケース
- 定型的な文書作成や小規模変更では Auto が選んだ低コストモデルを使う。
- 複雑・高リスクな作業では、タスク分割、追加レビュー、テストを行う。
- 要求、設計、計画、実装を必要な Skill に委譲する。

## 5. 機能要件
- カスタムエージェントはモデルを固定せず、Copilot の Auto 選択を既定とする。
- モデル固定が必要な場合は、理由と見直し条件を定義内に記載する。
- Skill は `.github/skills/<skill-name>/SKILL.md` 形式とし、`name` と `description` を含む。
- 共通指示は、文書化の要否、検証、セキュリティ、停止条件を明確にする。
- 指示の重複を避け、常時適用する規則と必要時のみ使う Skill を分離する。

## 6. 非機能要件
- 性能: 不要な探索、重複読込、同一作業の再実行を避ける。
- セキュリティ: 最小権限、入力検証、秘密情報検査、依存関係確認を求める。
- 可用性: 特定モデルが利用できない場合も Auto 選択で継続できる。
- 運用性: テンプレート利用者が適用箇所と更新方法を README から判断できる。

## 7. 受け入れ基準
- すべての Skill が公式の `SKILL.md` 構造である。
- Auto 優先と、品質を保つためのエスカレーション条件が文書化されている。
- 要求から検証までのトレーサビリティがテンプレートに含まれる。
- Markdown、YAML、リンク、文字化けに明らかな不備がない。

## 8. 未決事項
- 組織ポリシーで Auto を強制するかは、各導入先の管理者が決定する。
- 個別エージェントでのモデル固定は、導入先の利用可能モデルと料金体系に合わせて判断する。
