# Copilot カスタマイズ実装計画

## 1. 対象
共通指示、Agent Skills、関連テンプレートと利用手順の改善。

## 2. 前提
- 要求仕様: `docs/requirements/copilot-customization.md`
- 詳細設計: `docs/design/copilot-customization.md`
- カスタムエージェントはモデルを原則固定せず Auto 選択に委ねる。

## 3. タスク分解
- [x] 共通指示へモデル選択、品質ゲート、停止条件を追加する。
- [x] 既存 Skill を公式ディレクトリ構造へ移行する。
- [x] 各 Skill に入力、手順、出力、完了条件を追加する。
- [x] README と PR テンプレートを更新する。
- [ ] 構造、構文、差分、セキュリティを検証する。

## 4. 依存関係
共通方針を定義した後、Skill と利用手順を同じ方針に揃える。

## 5. リスクと対策
- 導入先で Auto が無効: 組織ポリシーと利用可能モデルを確認する旨を明記する。
- 指示過多: 常時ルールを絞り、詳細手順を Skill に分離する。
- 品質低下: 高リスク条件、テスト、独立レビューをモデル選択と分離して必須化する。

## 6. テスト計画
- ファイル構造と YAML frontmatter の確認。
- Markdown/YAML の静的確認。
- 旧 Skill パスや文字化けの残存確認。
- 差分レビュー、秘密情報検査、CodeQL 検査。

## 7. 完了条件（Definition of Done）
- 要求仕様と詳細設計の受け入れ基準を満たす。
- 関連ドキュメントと設定に矛盾がない。
- 検証結果と既知の制約を報告できる。
