# Copilot カスタマイズ実装計画

## 1. 対象
共通指示、Agent Skills、関連テンプレートと利用手順の改善。

## 2. 前提
- 要求仕様: `docs/requirements/copilot-customization.md`
- 詳細設計: `docs/design/copilot-customization.md`
- カスタムエージェントはモデルを原則固定せず Auto 選択に委ねる。

## 3. タスク分解
- [x] 共通指示へモデル選択、品質ゲート、停止条件を追加する。
- [x] 既存 Skill を公式ディレクトリ構造へ移行する。
- [x] 各 Skill に入力、手順、出力、完了条件を追加する。
- [x] README と PR テンプレートを更新する。
- [x] 構造、構文、差分、セキュリティを検証する。
- [x] 言語別指示の要求、対象拡張子、参照規約を要求仕様と詳細設計に追加する。
- [x] C、C++、C#、Python、JavaScript、TypeScript のパス固有指示を追加する。
- [x] README と共通指示を言語別指示の構成に合わせて更新する。
- [x] frontmatter、拡張子の重複、参照 URL、差分を検証する。

## 4. 依存関係
共通方針を定義した後、Skill と利用手順を同じ方針に揃える。

## 5. リスクと対策
- 導入先で Auto が無効: 組織ポリシーと利用可能モデルを確認する旨を明記する。
- 指示過多: 常時ルールを絞り、詳細手順を Skill に分離する。
- 品質低下: 高リスク条件、テスト、独立レビューをモデル選択と分離して必須化する。
- 規約の競合: 導入先の formatter、linter、コンパイラ設定と既存規約を優先する。
- 適用漏れ・重複: 拡張子一覧を設計で固定し、glob の重複と代表パスを検証する。
- 外部規約の変更: 規約名と提供元 URL を記載し、メンテナンス時にリンクを確認する。

## 6. テスト計画
- ファイル構造と YAML frontmatter の確認。
- Markdown/YAML の静的確認。
- 旧 Skill パスや文字化けの残存確認。
- 言語別 instruction の frontmatter、対象拡張子、参照 URL の確認。
- 差分レビュー、秘密情報検査、CodeQL 検査。

## 7. 完了条件（Definition of Done）
- 要求仕様と詳細設計の受け入れ基準を満たす。
- 関連ドキュメントと設定に矛盾がない。
- 検証結果と既知の制約を報告できる。

## 8. ロールバック
言語別指示に適用上の問題がある場合は、該当する `.github/instructions/*.instructions.md` と README、共通指示の関連記述を削除し、追加前の共通指示へ戻す。
