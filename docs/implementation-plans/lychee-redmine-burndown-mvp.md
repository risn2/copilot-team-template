# Lychee Redmine バーンダウン MVP 実装計画

## 1. 対象
スプリント主導のユーザー別バーンダウン MVP と関連文書の追加。

## 2. 前提
- 要求仕様: `docs/requirements/lychee-redmine-burndown-mvp.md`
- 詳細設計: `docs/design/lychee-redmine-burndown-mvp.md`
- 既存リポジトリにはビルド・テスト基盤がないため、静的ファイルと targeted な構文確認・手動確認で検証する。

## 3. タスク分解
- [ ] 要求仕様と整合する詳細設計・前提を文書化する。
- [ ] スプリント中心のサンプルデータモデルを作成する。
- [ ] ユーザー別バーンダウンを表示する最小 UI を実装する。
- [ ] クエリパラメータ、エラー表示、空状態の最小制御を実装する。
- [ ] README に MVP の場所と確認方法を追記する。
- [ ] 構文確認、手動確認、秘密情報確認、レビューを実施する。

## 4. 依存関係
- 文書作成後にデータモデルを確定する。
- データモデル確定後に UI と描画ロジックを実装する。
- 実装完了後に検証、レビュー、セキュリティ確認を行う。

## 5. リスクと対策
- 実データ連携未実装: ドキュメントに明示し、JSON 契約を固定する。
- スプリント境界の解釈差異: Lychee 設定を正とする前提を requirements / design の両方に記載する。
- テスト基盤不足: 構文確認とブラウザ手動確認の結果を残す。

## 6. テスト計画
- `node --check` で JS 構文を確認する。
- JSON パース確認を行う。
- ローカル HTTP サーバーで `mvp/index.html` を開き、初期表示と切替動作を確認する。
- 変更ファイルに対して秘密情報スキャンを実施する。

## 7. 完了条件（Definition of Done）
- 要求仕様、詳細設計、実装計画が揃っている。
- スプリント期間を主軸にしたユーザー別バーンダウン MVP が動作する。
- 検証結果、制約、未解決事項を報告できる。
